# 涨停关联分析

基于外部涨停数据库（stockDb.db3）的 `stock_limit_up`（涨停全记录）与 `stock_hot_subject`（每日热门股）两张表，挖掘"A 涨停 → B 跟涨"的历史联动规律，并对单只涨停股做归因分析。

## 配置

在 `.env` 中配置外部库路径（留空则禁用本功能）：

```
CORRELATION_DB_PATH=D:/source/qym/electron-stock/stockDb.db3
```

要求源库中存在：

- `stock_limit_up`：日期取自 `SUBSTR(首次涨停时间, 1, 10)`（实测覆盖率 100%）
- `stock_hot_subject`：自带 `日期` 字段

统计产出表（`stock_pair_stats` / `stock_rise_attribution`）**与源表同库写入**，无需额外配置。

**注意**：构建会直接写源库；若采集进程正在写库，可能因 SQLite 锁竞争失败（已设 5 秒锁等待），建议盘后采集完成后再运行 `--build-correlation`。

首次使用前需构建统计表：

```bash
python main.py --build-correlation
```

## 使用

### 输入今日涨停股，找强关联跟风股

```bash
python main.py --related 002080.SZ
python main.py --related 002080.SZ --correlation-date 2026-08-05
```

输出该股历史强关联跟风股列表（样本数 ≥ 8、lift ≥ 1.4、次日平均涨幅 ≥ 1.5% 才入选），每只 B 附 T+1 延续率、lift、次日平均涨幅，以及结合当日盘面的操作提示（T+0 跟风候选 / 已联动 / T+1 候选观察竞价）。

### 输入今日涨停股，归因上涨原因

```bash
python main.py --attribute 002080.SZ
```

按优先级输出归因链：

1. **龙头带动**：历史上反复带动该股的龙头今日先于它涨停（附历史联动次数 / 延续率 / lift）
2. **板块带动**：同板块今日存在更早封板的涨停股，且满足以下之一：板块多家涨停（板块效应）、或该股为 ≥2 连板的龙头（单一高位连板龙头同样构成有效带动）；附板块涨停家数 / 板块上涨原因
3. **独立行情**：以上均不命中，输出涨停强度评分（首板时间分档 + 换手率 + 买入锁仓 + 炸板次数）

归因结果落 `stock_rise_attribution` 表（产出库）。

## 统计口径

**重要**：`stock_hot_subject` 是热门股表——股票因上涨才入选（实测涨跌幅最小值 ≈ 4.6%），因此"B 涨跌幅 > 0"在热门股 universe 内无区分度，不能用涨跌幅做胜率。本模块的核心指标为**热度延续**：

- **龙头池**：`stock_limit_up` 中 `连续涨停天数 = 1`（首板）且非新股的股票
- **候选 B 池**：A 首板日热门 ∪ 次日热门（龙头本身除外），覆盖**当日跟风**与**次日跟风**两种模式（如 A 周一首板、B 周二才上热门，计为"次日跟风"事件）
- **关联通道**：
  - `sector`：A 的 `关联板块名称` 与 B 的 `板块名称` 相同（B 取事件日记录）
  - `theme`：A 的 `个股涨停原因` 与 B 的 `简介/研报标题` 字符 bigram 重合度（overlap coefficient）≥ 0.35，且未被 sector 通道占用
- **联动事件**：A 首板窗口内（当日或次日）B 上热门
- **延续事件**：联动事件后一交易日 B 仍热门
- **B 无条件延续率** = P(B 下一交易日仍热门 | B 当日热门)，即 B 自身热度惯性基准
- **lift** = P(B 延续 | A 首板联动) / B 无条件延续率，衡量 A 涨停对 B 热度延续的真实增量
- **描述性指标**（参考）：B 跟风日涨停次数、跟风日/延续日平均涨幅（源表涨跌幅为小数比例，展示时换算为百分比；延续日涨幅仅统计延续样本，偏高仅供参考）

## 已知口径限制（一期）

- 统计窗口上限为 hot_subject 的覆盖区间（约 140 个交易日，2025 年初起）
- 无分钟级数据，T+0 跟随以 B 当日涨跌幅近似
- 归因方向依赖"涨停时间早者为龙头"的假设
- 源表板块体系未完全对齐（hot_subject 163 个板块中 159 个在 limit_up 1004 个板块内），板块通道仅覆盖交集部分
